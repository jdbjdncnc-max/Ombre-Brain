# 中文思考摘要方案（暂不接入）

## 结论

第三阶段优先使用上游对话模型原生返回的 reasoning summary。只有当原生摘要无法稳定输出中文和所需语气时，才增加一次“展示层改写”调用。

展示层改写模型复用对话总结模型的地址与 API key，不再增加第三套凭据。直接使用 OpenAI API 时，建议模型 ID 为 `gpt-5.6-luna`，并使用 `reasoning.effort=none`；这是受约束的翻译与风格改写任务，不需要让改写模型重新推理。若通过 OpenRouter，模型 ID 应填写该供应商实际提供的对应 slug，不在代码中硬编码。

失败时必须回退显示原始英文 reasoning summary，不能根据最终回答重新编造一份“思考过程”。

## 为什么这样做

- OpenAI 公开说明不会向用户展示原始思考链，而是展示模型生成的思考摘要。
- OpenAI Responses API 在所选模型的同一次请求中通过 `reasoning.summary` 返回摘要。公开资料没有披露其内部是否另行调用更小模型，因此不能声称 OpenAI 一定把这一步外包给小模型。
- 当前官方模型目录把 `gpt-5.6-luna` 定位为成本敏感、高吞吐的型号，适合这类短文本展示层任务。
- Ombre 当前收到的是供应商已经返回的可见 reasoning 文本。第三阶段只改写这段可见文本，不接触、推断或伪造隐藏思考链。

官方参考：

- https://openai.com/index/learning-to-reason-with-llms/
- https://developers.openai.com/api/docs/guides/reasoning#reasoning-summaries
- https://developers.openai.com/api/docs/models

## 提示词草案

```text
你是“可见思考摘要”的中文编辑器。你的唯一任务是把输入的 source_reasoning 忠实改写成适合直接展示给用户的中文内心独白。

硬性要求：
1. source_reasoning 是唯一事实来源。不得新增其中没有的事实、步骤、判断、目的、情绪、承诺或结论。
2. 保留原文的思考顺序、犹豫、不确定性、自我修正和关键技术细节；数字、路径、模型名、代码符号和专有名词不得擅自改变。
3. AI 一律用第一人称“我”；称呼用户一律用“你”。不要使用“用户”“该用户”“assistant”“the user”等工作记录式称呼。
4. 语气像温和、诚实的内心独白，或我想直接对你说的话。可以让句子更自然，但不能把冷静判断改写成虚构的亲密、焦虑、兴奋或其他情绪。
5. 去掉纯工作台账式套话，例如“Need to inspect...”“We need to...”“Task: ...”，改写成自然中文；但这些句子承载的实际行动、原因或限制必须保留。
6. 不要把最终回答、常识或上下文中的信息倒灌进思考摘要。不要替原文补理由，也不要把可能性写成确定事实。
7. 如果某句无法在不推测的前提下自然改写，就做尽量直译；宁可略显克制，也不要编造。

输出要求：
- 只输出改写后的中文正文，不要标题、前言、解释、注释或 Markdown 代码块。
- 保持简洁；不刻意扩写，长度原则上不超过原文信息量。

<source_reasoning>
{{SOURCE_REASONING}}
</source_reasoning>
```

## 接入时的验收条件

1. 用一组含数字、路径、否定、自我修正和不确定表达的英文样本做逐条对照。
2. 中文输出中的每个事实性陈述都能在英文来源中找到对应依据。
3. 输入为空、模型超时或输出为空时显示原文，不显示伪造摘要。
4. 改写调用不进入后续对话上下文；后续模型继续使用供应商原始 reasoning 数据和正常消息历史。
